# 演讲培训技能

## Overview

本 skill 辅助演讲者完成演讲/培训材料的全流程制作：从主题信息收集、名人名言核查、完整逐字稿、演示指令脚本，到 HTML 格式 PPT。

**与 frontend-slides 的分工（重要）：**

| 职责 | 归属 |
|------|------|
| 内容：信息收集、名言核查、逐字稿、演示脚本、PPT 大纲 | 本 skill |
| 视觉：风格预览、幻灯片生成、部署 URL、PDF 导出 | `frontend-slides` skill |

Step 5 调用 frontend-slides 时**跳过其 Phase 1 提问**（信息本 skill 已收集），直接传交接包，从其 Phase 2（风格预览）开始。不要让用户回答两遍同样的问题。

## 核心产出物

| 产出物 | 文件命名规范 | 说明 |
|--------|-------------|------|
| 演讲逐字稿 | `{日期}培训素材/演讲逐字稿.md` | 含章节结构的完整演讲内容 |
| 演示指令脚本 | `{日期}培训素材/演示指令脚本.md` | 现场演示的分步指令 |
| HTML PPT | `{标题}-{日期}.html` | 独立运行的幻灯片（frontend-slides 生成） |
| PPT 降级大纲 | `{日期}培训素材/PPT-大纲.md` | frontend-slides 缺失时的 Markdown 版 |

## Workflow

### Step 0: 快速模式判断 + 断点检测

**断点检测**：先检查工作目录下是否已有 `{日期}培训素材/.progress.json`。存在则读取，询问用户"检测到上次进度（已完成 Step N），继续还是重来？"，继续则从断点步骤开始。

**快速模式**：如果用户首条消息已包含主题 + 受众 + 时长，不做完整问诊。用一条消息回显推断出的全部信息（含默认值：场合、密度、演讲者信息待补），让用户确认或纠正，然后直接进 Step 2。

**进度记录**：每完成一个 Step，更新 `.progress.json`：

```json
{"topic": "...", "audience": "...", "duration": "30min", "occasion": "...", "style": "干货型", "completed_steps": [1, 2], "updated": "YYYY-MM-DD"}
```

### Step 1: 主题信息收集（完整问诊）

使用 `AskUserQuestion` 工具提问。**注意**：单次最多 4 个问题，分两批。

**第一批（4 个问题）**：
1. **演讲主题** — 具体要讲什么？
2. **目标受众** — 业务/HR/技术/高管？人数规模？
3. **时长** — 15min / 30min / 45min？
4. **场合** — 园区分享 / 内部培训 / 大会演讲 / 其他？

**第二批（4 个问题）**：
5. **核心信息** — 用户想传递的 2-3 个关键观点
6. **参考资料** — 是否有现成的文档、图片、素材？（如有请用户提供）
7. **演讲者信息** — 姓名、职位、公司（用于封面）
8. **会后分发** — PPT 只现场讲，还是会后还要发给别人自己看？（决定密度模式和分发方式）

**受众风格映射**（决定逐字稿语气与 PPT 风格倾向）：

| 受众 | 逐字稿风格 | PPT 风格提示 |
|------|-----------|-------------|
| 技术 | 干货型：多数据、多演示、少铺垫 | 结构化网格、代码/终端元素 |
| 业务 | 故事型：案例驱动、场景代入 | 大图 + 大字标语 |
| 园区/泛众 | 轻松型：段子开场、比喻多 | 明快色彩、插画感 |
| 高管 | 精炼型：结论先行、每章一句话可带走 | 极简、留白多、高级感 |

按受众类型**追问 1 个针对性问题**（如技术受众问"想现场演示还是只讲原理"，高管问"最想让他们会后拍板什么"），不要机械走完固定清单就结束。

### Step 2: 名人名言筛选（如需要）

根据主题，用 `WebSearch` 检索该领域权威人士的**最新公开观点**，不要凭记忆引用。

**筛选标准：**
- 有名有姓，禁止"有专家表示"式模糊引用
- 时间新鲜：优先演讲日期前 12 个月内的发言
- 与演讲主题直接相关
- 每位名人 1-2 句金句，宁缺毋滥

**核查要求（必须）：** 每条引用在写入逐字稿前，用 `WebSearch`（必要时 `WebFetch` 原文页面）确认三件事——原话大意无误、职位头衔当前有效、时间出处可溯源。核查不过的引用直接弃用，不降级为模糊引用。

### Step 3: 生成演讲逐字稿

**结构模板（按总时长比例分配，非固定分钟数）：**

```
## 第一章：观点引入（~10%）
- 用一个反常识判断或数据开场
- 引用 1-2 位名人的话
- 提出核心矛盾

## 第二章：是什么（~20%）
- 用比喻解释核心概念
- 旧模式 vs 新模式对比
- 包含演示环节（可嵌入 PPT 页码引用）

## 第三章：实战场景（~30%）
- 2-3 个真实使用案例
- 每个案例：背景 → 操作 → 结果
- 可引用用户提供的截图

## 第四章：为什么（~20%）
- 平台/方案对比（如涉及选型）
- 优势拆解
- 最新动态

## 第五章：未来期待（~10%）
- 短期可实现的能力
- 个人/企业落地建议

## 收尾（~10%）
- 回扣开场观点
- 行动号召
- 结束语
```

章节结构可按主题增删，比例分配原则不变：实战场景永远是最大头。

**写作风格：**
- 按 Step 1 的受众风格映射定基调（干货型/故事型/轻松型/精炼型）
- 口语化、接地气，像在跟观众聊天
- 每个章节有具体的故事和数据支撑
- 禁止空洞的"赋能"类词汇，少用官话套话
- 名人名言要标注：姓名、职位、出处、时间
- 多用短句，少用复杂从句，演讲时容易卡壳

### Step 4: 生成演示指令脚本（如有现场演示）

**脚本结构：**

````
### 演示N：{演示名称}

**目标**：让 AI 帮你完成什么具体任务

**指令示例**：
```
粘贴给 AI 的具体指令
```

**操作步骤**：
1. 第一步
2. 第二步
3. 第三步

**风险提示**：
- 权限确认
- 备选 URL
- 失败处理
````

每个演示必须附**降级预案**：网络断了/工具挂了时，用什么截图或录屏兜底。

### Step 5: HTML PPT 生成（调用 frontend-slides skill）

**前置检查**：确认 `frontend-slides` skill 已安装（在可用 skills 列表中）。未安装 → 走本步末尾的降级方案。

**交接包（传给 frontend-slides，跳过其 Phase 1 提问）：**

| frontend-slides 需要 | 从哪来 |
|---------------------|--------|
| Purpose | Step 1 的场合（园区分享/内部培训 → Internal presentation；大会 → Conference talk） |
| Length | 按大纲映射规则估算页数（见下） |
| Content | 已就绪 —— Step 3 逐字稿的章节大纲 + 各章金句 |
| Density | Step 1 问题 8：只现场讲 → Low density / speaker-led；会后要发阅读 → 与用户确认是否 High density |
| 图片素材 | Step 1 收集的素材，走 frontend-slides 的 Step 1.2 图片评估流程 |

**额外约束（在交接时明确带入 frontend-slides 流程）：**
- 投影环境优先亮色系风格（warm cream / light background），风格预览至少 2 个亮色选项
- 风格倾向参考 Step 1 受众风格映射的"PPT 风格提示"列
- 演示页需要视觉高亮（区别于内容页），提醒观众"现在看现场操作"
- 封面含演讲者姓名、职位、公司

风格选择、幻灯片生成、视觉验证全部遵循 frontend-slides 的 Phase 2-3 流程，本 skill 不重复定义。

**大纲 → PPT 页面映射规则（通用，按逐字稿章节推导页数）：**

| 逐字稿内容 | 对应页面 |
|-----------|---------|
| 封面 | 1 页（标题 + 演讲者信息） |
| 名人名言 | 1 页（金句页，人名+头衔+出处） |
| 每个核心概念 | 1 页（比喻/对比图式） |
| 每个现场演示 | 1 页（高亮样式 + 演示目标一句话） |
| 每个实战案例 | 1 页（背景→操作→结果） |
| 选型/对比 | 1 页（对比表） |
| 未来期待 | 1 页 |
| 收尾 + 感谢 | 1-2 页 |

15 分钟演讲通常落在 12-16 页；30 分钟 20-28 页。页数超出就砍案例，不要压缩单页信息密度。

**降级方案（frontend-slides 未安装时）：**
1. 先提示用户安装：`zarazhangrui/frontend-slides`（一次安装长期使用，效果远好于降级版）
2. 用户不装或装不上 → 生成 `{日期}培训素材/PPT-大纲.md`（每页标题 + 要点 + 备注），再生成一个基础版单文件 HTML PPT：16:9 固定画布、键盘翻页、无花哨动画
3. 完成状态标记为 `DONE_WITH_CONCERNS`，说明差在哪

### Step 6: 分发（调用 frontend-slides Phase 6）

会后要发给别人时，**优先走 frontend-slides Phase 6**：
- **部署到 URL**（Vercel）— 任何设备可看，图片自动打包，推荐首选
- **导出 PDF** — 邮件/群发场景

只有用户明确要"发一个单 HTML 文件"且文件引用了本地图片时，才做 base64 嵌入版（`{标题}-嵌入版.html`）：

```python
import base64, os

folder = "素材文件夹路径"
html_file = "PPT.html"
images = {
    "头像.jpg": "image/jpeg",
    "截图.png": "image/png",
}

with open(os.path.join(folder, html_file), "r", encoding="utf-8") as f:
    html = f.read()

for filename, mime in images.items():
    with open(os.path.join(folder, filename), "rb") as f:
        b64 = base64.b64encode(f.read()).decode("ascii")
    html = html.replace(f'src="{filename}"', f'src="data:{mime};base64,{b64}"')

with open(os.path.join(folder, html_file.replace(".html", "-嵌入版.html")), "w", encoding="utf-8") as f:
    f.write(html)
```

## 完成状态协议

工作流结束时报告以下状态之一：

- **DONE** — 全部产出物生成完毕，名言已核查，素材就位
- **DONE_WITH_CONCERNS** — 主要产物已生成，但存在已知问题（缺图片、frontend-slides 降级、个别名言未能核实已弃用等），逐条列出
- **BLOCKED** — 缺少必填信息（主题/受众/时长）或依赖不可恢复，说明卡在哪、需要用户提供什么

## 文件输出规范

### 演讲逐字稿

路径：`{日期}培训素材/演讲逐字稿.md`

结构：
- 文件头（演讲标题、日期、演讲者）
- 素材索引表（章节 → 对应图片）
- 正文（分章节，含 Timing 预估）

### 演示指令脚本

路径：`{日期}培训素材/演示指令脚本.md`

结构：
- 概述（几个演示，核心目标）
- 每个演示的完整脚本（含降级预案）
- 演示前检查清单

## 素材收集清单

开始制作前，确认以下素材已就位：

- [ ] 演讲者头像（用于封面）
- [ ] 名人头像（如金句页需要）
- [ ] 实战场景截图（工具对话、自动化成果等）
- [ ] 产品/工具截图
- [ ] 其他与案例对应的图片

## 注意事项

1. **名人名言必须实时核查**：引用前用 WebSearch 确认原话、头衔、时间，优先演讲日期前 12 个月内的发言；核查不过直接弃用
2. **面向非技术受众**：解释技术概念时用比喻，不用术语
3. **投影环境**：优先亮色系风格，避免纯黑深色背景
4. **图片命名**：用有意义的命名，避免中文长文件名（部分系统兼容问题）
5. **不重复提问**：Step 1 收集的信息直接传给 frontend-slides，跳过其 Phase 1
6. **不自行手写 PPT HTML**（降级方案除外）：视觉生成一律走 frontend-slides，保证固定 16:9 stage、动画、部署链路可用
7. **每步落盘**：产出物写入 `{日期}培训素材/` 并更新 `.progress.json`，对话中断可续
